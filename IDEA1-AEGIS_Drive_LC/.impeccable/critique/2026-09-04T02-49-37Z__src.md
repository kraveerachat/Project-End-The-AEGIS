## Anti-patterns verdict

The approved result does not read as an AI-slop gallery. Accent gradients are limited to selected states, content cards remain solid, and glass is confined to shell surfaces. The initial pass did reveal visual drift rather than conceptual drift: an inverted Settings pill, a Dark avatar contrast collision, and cramped preview copy.

The deterministic scan returned 20 advisory/warning records. Most color and radius records identify intentional Neo additions that the existing `DESIGN.md` does not yet describe. Two `broken-image` records in `src/lib/vaultPreview.js` are false positives against runtime-generated preview markup, and the remaining legacy literal-color/radius records predate this feature.

## Overall impression

Neo feels like the same security product with a more composed enterprise shell, not a second application pasted over the first. The biggest opportunity was consistency at state boundaries: style persistence, selected navigation, and Dark fallback colors all needed to agree with the new semantic system.

## What's working

- Classic remains visually intact and Login never receives a UI-style attribute.
- Neo Light and Dark are intentionally distinct: shadow-led cool surfaces versus stepped graphite/navy surfaces.
- The confirmation flow is honest and reversible until the preference save succeeds.

## Priority issues

- **[P1] Fresh authentication discarded saved preferences.** The credential mapper omitted server-owned preferences, causing a successful save to revert at the next login. Fix: carry preferences from the verified account row into the new session and add a fresh-session regression test.
- **[P1] Neo Dark avatar initials had white-on-white fallback contrast.** Utility cascade precedence overrode the requested accent background. Fix: add a Neo-scoped semantic avatar class.
- **[P2] Mobile language options were 41×44px.** This missed the requested 44×44 floor. Fix: enforce a Neo mobile `min-width` as well as `min-height` for segmented options.
- **[P2] Settings sub-navigation did not share the Neo selected-state language.** Fix: use the same blue-led selection token and restrained active shadow as the shell navigation.
- **[P3] Preview cards and warning text needed a polish pass.** Fix: widen the preview group and use an AA-capable semantic warning token in Neo Light.

## Persona red flags

- **Alex (power user):** The confirmation adds one deliberate step, justified because the switch ends the session. Escape and direct segmented controls keep the flow efficient.
- **Sam (accessibility-dependent):** Initial risks were Dark fallback contrast and 41px language targets. Radio semantics, labelled dialog, focus management, Escape, and reduced-motion handling were already present.
- **Riley (stress tester):** The live browser test found the fresh-session preference loss that current-session tests had missed; a logout/re-login test now guards it.

## Minor observations

- At 1280px, the wider preview group improves copy wrapping while preserving the existing responsive row shape.
- The dashboard's unavailable states remain truthful and visually legible in both Neo themes.
- No horizontal overflow appeared on any authenticated route or at 390×844.

## Questions to consider

- Should a future release add contextual help for the broader Settings taxonomy, or is inline explanation the preferred enterprise posture?
- Should the same blue-led active treatment eventually extend to other secondary navigation surfaces after adoption data is available?
