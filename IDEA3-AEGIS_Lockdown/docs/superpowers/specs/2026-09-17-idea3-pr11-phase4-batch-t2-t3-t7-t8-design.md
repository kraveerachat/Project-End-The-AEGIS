## 1. Purpose

This batch consolidates the remaining Phase 4 work that can be developed and
verified entirely inside the repository without mutating the Core, Server,
IDEA2 runtime, Mosquitto production service, or physical ESP32.

The batch is intended to reduce review/PR overhead while preserving the live
stage gates already established for PR11.

The batch does not claim that Phase 4 runtime is complete.

## 2. Approved repository scope

### T2 — G-10 + G-14

Provide safe broker material rendering and an isolated broker validation
harness.

Required properties:

- device identity is `aegis-relay-01`;
- Core identity is `idea3-core`;
- device MQTT identity is `idea3-dev-aegis-relay-01`;
- passwords are read from files and are never passed as plaintext command-line
  arguments;
- rendered ACL material substitutes `device-id` exactly;
- password database material is created without `mosquitto_passwd -b`;
- unsafe secret-file permissions fail closed;
- existing output is not silently overwritten;
- temporary broker validation:
  - binds loopback only;
  - refuses production port 8883;
  - never invokes systemctl;
  - never writes `/etc/mosquitto`;
  - validates TLS;
  - validates Core authentication;
  - validates device authentication;
  - validates the exact ACL matrix;
  - validates anonymous rejection;
  - validates retained-message rejection;
  - stops the temporary process;
  - proves no listening residue remains.

T2 tests use only throwaway test passwords and PKI.

No real owner secret is generated by repository tests.

## 5. T7 — G-16 non-blocking firmware Wi-Fi join

Replace the blocking Wi-Fi connection loop in ESP32 startup with a
non-blocking state/timing flow.

Safety behavior remains fail-secure:

- boot begins with relay CUT;
- loss of Wi-Fi does not restore connectivity;
- MQTT is not treated as available before Wi-Fi is ready;
- dead-man / containment safety behavior is preserved;
- reconnect attempts do not indefinitely block the firmware main loop;
- no static-IP implementation is introduced in this batch;
- DHCP remains the selected addressing behavior.

Repository acceptance must include source-level tests and, when the existing
project toolchain is available, firmware compilation.

Physical ESP32 verification remains L8 and is not claimed by this batch.

## 6. T8 — repository-safe G-11 portion

Implement only the portion of G-11 that can be proven without a physical ESP32
or Phase 3 Core installation.

The canonical firmware NVS contract remains namespace:

    aegis-p1

schema:

    1

Required fields remain aligned with firmware:

- device_id
- wifi_ssid
- wifi_psk
- broker
- mqtt_user
- mqtt_pass
- ntp
- k_c2d
- k_d2c
- seq_hi

The repository provisioning tooling must:

- validate schema 1;
- validate `device_id`;
- validate broker hostname profile;
- validate MQTT username profile;
- validate two independent protocol keys;
- reject zero/demo/identical protocol keys;
- avoid printing secret values;
- avoid placing secret values in subprocess argv;
- provide deterministic non-secret validation output;
- provide testable provisioning/material preparation behavior;
- maintain parity with firmware field names.

The repository may provide a secure owner-run key-generation procedure/tool,
but tests must use synthetic/temporary values only.

This batch does not perform:

- physical ESP32 NVS write;
- firmware flash;
- Production serial provisioning;
- Production credential creation;
- Core credential installation;
- T9 `LoadCredential=` integration;
- NVS encryption.

NVS encryption remains optional post-PR11 hardening unless separately chosen.

Therefore this batch may mark only the repository-safe T8 slice complete.
Full G-11 remains dependent on later delivery/live evidence.
