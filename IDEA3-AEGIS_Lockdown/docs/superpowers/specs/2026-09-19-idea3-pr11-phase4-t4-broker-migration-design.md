## 4. OD-08 — owner decision

Owner approval, 2026-09-19:

> Use a separate TLS-only Mosquitto instance for IDEA3 on 8883. Preserve the
> legacy Mosquitto 1883 service and the `aegis` user unchanged in T4. Removal
> or shutdown of 1883 is a separate future gate and is outside T4.

Binding consequences:

- T4 must not edit, replace, include, restart, stop, disable, or otherwise
  reconfigure `mosquitto.service`.
- T4 must not edit `/etc/mosquitto/mosquitto.conf`,
  `/etc/mosquitto/passwd`, or the legacy `aegis` identity.
- The IDEA3 instance is TLS-only and has no 1883 listener.
- The IDEA3 instance uses only the IDEA3 identities and ACL generated by T2.
- Removal of legacy 1883 is explicitly out of scope.

## 5. Target architecture

The repository will define a distinct IDEA3 broker service:

```text
legacy:
  mosquitto.service
  wildcard :1883
  legacy /etc/mosquitto tree
  user aegis
  PRESERVED BYTE/STATE BOUNDARY

IDEA3:
  aegis-idea3-mosquitto.service
  127.0.0.1:8883
  <AEGIS_AP_ADDRESS>:8883
  TLS 1.2+
  allow_anonymous false
  IDEA3-only password database
  IDEA3-only ACL
  persistence false
  retain_available false
```

There is no config include from the legacy Mosquitto tree and no shared
password database. The separate service must launch Mosquitto with the rendered
IDEA3 configuration directly.

The existing repository broker template remains the protocol/security
authority. T4 adds the deployment boundary needed to run it as a distinct
service without changing the legacy instance.

## 7. G-07 migration contract

Before any future L6b apply:

- L6a must PASS with separately authorized live material.
- L5 must PASS.
- same-day L6b owner authorization must exist.
- fresh K3 must exist.
- §10 preservation must be satisfiable.
- the legacy Mosquitto baseline must be captured and checksummed.
- the rendered IDEA3 config, unit, ACL/password paths, and PKI paths must pass
  repository validation.

A future L6b apply may install/start only the separate IDEA3 instance. It must
not restart the legacy broker.

L6b verification must prove:

- legacy `mosquitto.service` state and PID did not change;
- legacy config-tree and password-database digests did not change;
- legacy wildcard 1883 listener set did not change;
- legacy user `aegis` remains present;
- IDEA3 8883 listens only on loopback and the AP address;
- no wildcard 8883 and no 8883 on `enp62s0`;
- IDEA3 TLS/identity/ACL checks pass;
- no new forwarding/NAT/default-route drift;
- §10 preservation passes.

## 8. PF-01 explicit negative control

OD-08 preserves wildcard legacy 1883. Therefore AP isolation cannot rely on an
implicit catch-all.

The repository must retain and explicitly test the T5 firewall requirement
that AP-originated TCP/1883 is dropped while AP TCP/8883 and UDP/123 are
handled only by their reviewed rules.

Future live verification at L4/L6b must show that an AP-subnet source cannot
reach legacy 1883.

No T4 artifact may add an allow rule for AP TCP/1883.

## 9. Fail-closed validation

Repository validation must reject at least:

- any IDEA3 `listener 1883`;
- wildcard `listener 8883`;
- 8883 bound to the uplink address/interface;
- inclusion of the legacy Mosquitto config tree;
- use of `/etc/mosquitto/passwd` by the IDEA3 instance;
- the legacy `aegis` user in the IDEA3 ACL/password contract;
- a service unit that starts/restarts/stops `mosquitto.service`;
- unresolved placeholders in rendered live artifacts;
- missing TLS CA/cert/key directives;
- anonymous access;
- retained-message availability;
- any rollback that reopens plaintext as a fallback.

## 10. Rollback model

Rollback is stage-local and idempotent.

For the separate-instance OD-08 topology, rollback means:

1. stop/disable only `aegis-idea3-mosquitto.service`;
2. remove only files installed by the T4/L6b handler;
3. preserve owner-held PKI/credential material unless its own procedure says
   otherwise;
4. verify the legacy broker state/listeners/config/password database equal the
   pre-stage capture;
5. capture rollback evidence and require PRE→RB comparison to PASS with no
   allow files.

Rollback must never restart or rewrite legacy 1883 merely to make verification
pass.
