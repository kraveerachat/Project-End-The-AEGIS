# LLM Wiki Schema & Operational Rules

> This document defines the conventions, directory layout, and operational workflows for maintaining the **AEGIS System LLM Wiki**. Any LLM Agent operating on this vault MUST follow these guidelines.

---

## 🏛️ Directory Structure

```
AEGIS_Knowledge/
├── .schema.md                # Schema & operational workflows
├── index.md                  # Master catalog of all wiki pages
├── log.md                    # Chronological append-only record of all actions
├── 00–05 … .md               # Canonical module/system notes — numbered top-level notes
│                             #   (e.g. "03 - 📹 IDEA2 AEGIS Monitor.md"). These ARE the
│                             #   module docs; there is no separate modules/ folder.
├── raw/                      # Immutable raw sources (AEGIS_Project_Knowledge.md & AEGIS_System_Design.docx)
├── concepts/                 # Architectural & security concept wiki pages
└── entities/                 # Hardware, network, and team entity wiki pages
```

> **Note (2026-07-25)**: A `modules/` folder was retired. Module documentation lives
> in the numbered top-level notes (`00 …` – `05 …`), which are the canonical home; the
> only file ever placed under `modules/` was an empty 0-byte stub and has been removed.

---

## 🏷️ Page Conventions

Every Wiki page MUST include standard YAML frontmatter:

```yaml
---
title: Page Title
tags: [tag1, tag2]
type: [module | concept | entity | summary]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: ["[[raw/AEGIS_Project_Knowledge_v7]]", "[[raw/AEGIS_System_Design_extracted]]"]
---
```

Use Obsidian **Wikilinks** (`[[Page Name]]`) for all cross-references between concepts, entities, and modules.

---

## ⚡ Core Operations

### 1. Ingest Workflow (`Ingest`)
When a new raw document is placed in `raw/`:
1. **Read & Extract**: Extract key facts, architectures, entities, decisions, and network details.
2. **Synthesize & Cross-reference**: Create or update the relevant canonical numbered top-level note (e.g. `03 - 📹 IDEA2 AEGIS Monitor.md`) plus any related pages under `concepts/` and `entities/`.
3. **Link**: Insert bidirectional `[[Wikilinks]]` between related topics.
4. **Update Catalog**: Add/update page entries in `index.md`.
5. **Log**: Append entry to `log.md` (`## [YYYY-MM-DD] ingest | <Source Title>`).

### 2. Query Workflow (`Query`)
When answering user queries:
1. Search `index.md` first to locate relevant entity/concept pages.
2. Synthesize answer with citations to specific wiki pages (`[[Page Name]]`).
3. If the user query uncovers a valuable comparison or new synthesis, **file it back into the wiki** as a new page under `concepts/`.

### 3. Health-Check Workflow (`Lint`)
Periodically verify the wiki health:
- Flag contradictions between pages.
- Check for orphan pages lacking inbound `[[Wikilinks]]`.
- Verify hardware/software status claims ("Code written" vs "Tested and passed").
- Ensure all entries in `index.md` exist and are categorized correctly.
