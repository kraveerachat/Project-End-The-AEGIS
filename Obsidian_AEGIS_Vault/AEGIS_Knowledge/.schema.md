# LLM Wiki Schema & Operational Rules

> This document defines the conventions, directory layout, and operational workflows for maintaining the **AEGIS System LLM Wiki**. Any LLM Agent operating on this vault MUST follow these guidelines.

---

## 🏛️ Directory Structure

```
AEGIS_Knowledge/
├── START_HERE.md                  # Single entry point; Kla-owned integration surface
├── index.md / .schema.md          # Catalog and rules; Kla owner-only
├── core/                          # Stable shared architecture and integration contracts
│   ├── core-moc.md                 # Shared operating dashboard and integration entry point
│   ├── system-overview.md         # Embed-only overview shell
│   ├── system-context.md          # Preserved system architecture detail
│   └── integration-points.md      # Cross-module contracts and boundaries
├── idea1/                         # Kla-owned MOC + current status
├── idea2/                         # Pub-owned MOC + current status
├── idea3/                         # Music-owned MOC + current status
├── infrastructure/                # Kla-owned operational truth
│   ├── network/ ├── server/ ├── remote-access/ └── deployment/
├── concepts/ / entities/ / ethics/ / summaries/
├── raw/                           # Immutable source material
├── 90-Status/
│   ├── integration-queue.md       # Kla integrates reviewed cross-area requests
│   └── logs/
│       ├── _template.md
│       └── YYYY-MM-DD_HHMMSS_<owner>_<topic>.md  # immutable receipts
├── log.md                         # Frozen legacy history; never append
└── AEGIS_Knowledge_Network.canvas # Curated navigation map, not the source of truth
```

The old numbered top-level module layout was migrated on 2026-08-13. Wikilinks now use canonical paths so ownership boundaries are visible in both Git diffs and Obsidian.

## 🏷️ Page Conventions

Every Wiki page MUST include standard YAML frontmatter:

```yaml
---
title: Page Title
tags: [tag1, tag2]
type: [moc | module | concept | entity | summary | wiki-admin]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: ["[[raw/AEGIS_Project_Knowledge_v7]]", "[[raw/AEGIS_System_Design_extracted]]"]
owner: [kla | pub | music]
edit_policy: [owner-only | owner-writable | append-by-new-file | immutable-source]
---
```

Policy meanings:

- `owner-only`: shared integration/governance note; only its owner edits it directly.
- `owner-writable`: canonical workstream note; its owner updates it, other areas submit a receipt request.
- `append-by-new-file`: every task adds a uniquely named file and never edits an existing receipt.
- `immutable-source`: source evidence is read-only; derived facts go into canonical notes.

Use Obsidian **Wikilinks** (`[[Page Name]]`) for all cross-references between concepts, entities, and modules.

## ⚡ Core Operations

### 1. Ingest Workflow (`Ingest`)
When a new raw document is placed in `raw/`:
1. **Read & Extract**: Extract key facts, architectures, entities, decisions, and network details.
2. **Synthesize & Cross-reference**: Update only the canonical note owned by the task area (for example `idea2/idea2-status.md`).
3. **Link**: Insert bidirectional `[[Wikilinks]]` between related topics.
4. **Update Catalog**: Add/update page entries in `index.md`.
5. **Receipt**: Create one new timestamped file in `90-Status/logs/` from `_template.md`.
   Include source paths, verification evidence, canonical notes, shared surfaces,
   integration requests, and limitations. Do not append to the legacy `log.md`.

### 2. Completed Task Workflow (`Task Receipt`)

1. Use one task branch and keep changes inside its selected area.
2. Run affected tests and record exact commands and results.
3. Update canonical notes only where durable implementation facts changed.
4. Create exactly one new `90-Status/logs/YYYY-MM-DD_HHMMSS_<owner>_<topic>.md`.
5. Declare cross-scope files for integration review and open one Pull Request.

Area routing is fixed: `idea1`/`infrastructure`/`shared` → Kla, `idea2` → Pub, `idea3` → Music. A contributor never edits another area merely to announce their own work.

Receipts use `edit_policy: append-by-new-file`: never edit another task's receipt.
The legacy shared task log is frozen so parallel IDEA branches cannot overwrite it.

### 3. Query Workflow (`Query`)
When answering user queries:
1. Search `index.md` first to locate relevant entity/concept pages.
2. Synthesize answer with citations to specific wiki pages (`[[Page Name]]`).
3. If the user query uncovers a valuable comparison or new synthesis, **file it back into the wiki** as a new page under `concepts/`.

### 4. Vault Scope (`Scope`) — **do not skip this**

Obsidian must be opened on **`Obsidian_AEGIS_Vault/AEGIS_Knowledge`**, not on the repository root.

Opening the repo root indexes every Markdown file in the tree — **374 from `node_modules/`** plus **~120 from the four duplicated AI-skill trees** (`.claude/`, `.agents/`, `.cursor/`, `.gemini/`), against only ~45 real knowledge notes. That is what produced the scattered orphan graph of `README` / `LICENSE` / `CHANGELOG` / `SKILL` dots: **~92% of those nodes were never project knowledge.**

A safety net is configured in the repo root's `.obsidian/app.json` via `userIgnoreFilters`. If new noise appears in the graph, extend that list rather than deleting files — `node_modules/` is required to run the apps, and the duplicated skill trees are intentional (one per AI tool). See [[core/agent-operating-rules]].

### 5. Workspace Navigation and Historical Compatibility (`Navigate`)

Global Graph is an overview of the separated knowledge spaces, not the starting point for area work. Begin from [[core/core-moc]] for shared work or the relevant area MOC; use that MOC's Local Graph when exploring its immediate neighborhood.

Frozen historical links remain compatible through frontmatter `aliases`. When a canonical note is renamed or relocated, preserve its former title as an alias rather than creating a duplicate legacy note or rewriting frozen history.

### 6. Health-Check Workflow (`Lint`)
Periodically verify the wiki health:
- Flag contradictions between pages.
- Check for orphan pages lacking inbound `[[Wikilinks]]`.
- Verify hardware/software status claims ("Code written" vs "Tested and passed").
- Ensure all entries in `index.md` exist and are categorized correctly.
- Run `node scripts/validate-vault.mjs --vault Obsidian_AEGIS_Vault/AEGIS_Knowledge` and treat unresolved links, missing ownership metadata, malformed receipts and case collisions as failures. Orphans are warnings for human review.
