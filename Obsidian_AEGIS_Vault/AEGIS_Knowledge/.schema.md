# LLM Wiki Schema & Operational Rules

> This document defines the conventions, directory layout, and operational workflows for maintaining the **AEGIS System LLM Wiki**. Any LLM Agent operating on this vault MUST follow these guidelines.

---

## 🏛️ Directory Structure

```
AEGIS_Knowledge/
├── START_HERE.md             # ⭐ ENTRY POINT — read first, every session (type: moc).
│                             #   Orientation, agent reading protocol, knowledge-network
│                             #   diagram, full table of contents. Referenced from the repo's
│                             #   AGENTS.md and CLAUDE.md so agents load it automatically.
├── .schema.md                # Schema & operational workflows
├── index.md                  # Master catalog of all wiki pages (flat A–Z; START_HERE is guided)
├── log.md                    # Legacy shared operation log — frozen after guardrails
├── AEGIS_Knowledge_Network.canvas  # Visual relationship map of the whole vault
├── 00–07 … .md               # Canonical module/system notes — numbered top-level notes
│                             #   (e.g. "03 - 📹 IDEA2 AEGIS Monitor.md"). These ARE the
│                             #   module docs; there is no separate modules/ folder.
│                             #   06 = Agent Operating Rules, 07 = Design System (added 2026-08-06
│                             #   to give repo-root AGENTS/CLAUDE/PRODUCT/DESIGN docs a vault node).
├── raw/                      # Immutable raw sources (AEGIS_Project_Knowledge.md & AEGIS_System_Design.docx)
├── concepts/                 # Architectural & security concept wiki pages
├── entities/                 # Hardware, network, and team entity wiki pages
├── ethics/                   # HREC-SUT ethics/compliance forms
├── 90-Status/logs/           # Immutable one-file-per-task receipts for parallel work
│   ├── _template.md          # Required receipt structure
│   └── YYYY-MM-DD_HHMMSS_<owner>_<topic>.md
└── summaries/                # type: summary — history re-read BY CATEGORY instead of by date.
                              #   Curated durable summaries; task-level evidence lives in receipts.
```

> **Note (2026-07-25)**: A `modules/` folder was retired. Module documentation lives
> in the numbered top-level notes (`00 …` – `05 …`), which are the canonical home; the
> only file ever placed under `modules/` was an empty 0-byte stub and has been removed.

## 🏷️ Page Conventions

Every Wiki page MUST include standard YAML frontmatter:

```yaml
---
title: Page Title
tags: [tag1, tag2]
type: [moc | module | concept | entity | summary | wiki-admin]
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: ["[[raw/AEGIS_Project_Knowledge_v7]]", "[[raw/AEGIS_System_Design_extracted]]"]
---
```

Use Obsidian **Wikilinks** (`[[Page Name]]`) for all cross-references between concepts, entities, and modules.

## ⚡ Core Operations

### 1. Ingest Workflow (`Ingest`)
When a new raw document is placed in `raw/`:
1. **Read & Extract**: Extract key facts, architectures, entities, decisions, and network details.
2. **Synthesize & Cross-reference**: Create or update the relevant canonical numbered top-level note (e.g. `03 - 📹 IDEA2 AEGIS Monitor.md`) plus any related pages under `concepts/` and `entities/`.
3. **Link**: Insert bidirectional `[[Wikilinks]]` between related topics.
4. **Update Catalog**: Add/update page entries in `index.md`.
5. **Receipt**: Create one new timestamped file in `90-Status/logs/` from `_template.md`.
   Include source paths, verification evidence, canonical notes, shared surfaces,
   integration requests, and limitations. Do not append to the legacy `log.md`.

### 2. Completed Task Workflow (`Task Receipt`)

1. Use one task branch and keep changes inside its selected area.
2. Run affected tests and record exact commands and results.
3. Update canonical notes only where durable implementation facts changed.
4. Create exactly one new `90-Status/logs/YYYY-MM-DD_HHMMSS_<owner>_<topic>.md`.
5. Declare cross-scope files for integration review and open one Pull Request.

Receipts use `edit_policy: append-by-new-file`: never edit another task's receipt.
The legacy shared task log is frozen so parallel IDEA branches cannot overwrite it.

### 3. Query Workflow (`Query`)
When answering user queries:
1. Search `index.md` first to locate relevant entity/concept pages.
2. Synthesize answer with citations to specific wiki pages (`[[Page Name]]`).
3. If the user query uncovers a valuable comparison or new synthesis, **file it back into the wiki** as a new page under `concepts/`.

### 4. Vault Scope (`Scope`) — **do not skip this**

Obsidian must be opened on **`Obsidian_AEGIS_Vault/AEGIS_Knowledge`**, not on the repository root.

Opening the repo root indexes every Markdown file in the tree — **374 from `node_modules/`** plus **~120 from the four duplicated AI-skill trees** (`.claude/`, `.agents/`, `.cursor/`, `.gemini/`), against only ~45 real knowledge notes. That is what produced the scattered orphan graph of `README` / `LICENSE` / `CHANGELOG` / `SKILL` dots: **~92% of those nodes were never project knowledge.**

A safety net is configured in the repo root's `.obsidian/app.json` via `userIgnoreFilters`. If new noise appears in the graph, extend that list rather than deleting files — `node_modules/` is required to run the apps, and the duplicated skill trees are intentional (one per AI tool). See [[06 - 🤖 Agent Operating Rules]].

### 5. Health-Check Workflow (`Lint`)
Periodically verify the wiki health:
- Flag contradictions between pages.
- Check for orphan pages lacking inbound `[[Wikilinks]]`.
- Verify hardware/software status claims ("Code written" vs "Tested and passed").
- Ensure all entries in `index.md` exist and are categorized correctly.
