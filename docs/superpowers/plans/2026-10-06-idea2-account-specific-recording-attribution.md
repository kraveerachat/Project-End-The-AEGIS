# IDEA2 Account-Specific Recording Attribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Attribute every new verified recording to the authorized viewer's logical camera alias while retaining its exact physical Node/camera and producer-generation provenance, including concurrent aliases on one physical capture.

**Architecture:** Monitor obtains alias and generation from its existing transactional server-owned demand, then sends both over the authenticated Engine stream request. StreamHub binds each viewer lease to its alias; a small shared recording-authority snapshot lets one raw camera frame queue feed independent alias-scoped writers without a second camera open. After verified NAS transfer, Monitor validates the clip against historical demand/epoch/account/Node/physical relationships, including legitimately released rows, before insertion.

**Tech Stack:** Monitor Node.js/Express/PostgreSQL, Engine Python 3.12/Starlette/OpenCV, existing Ed25519 Identity Agent ingest and NAS sync.

**Spec:** `docs/superpowers/specs/2026-10-06-idea2-account-specific-recording-attribution-design.md` (commit `60d03383b0b48e99807ee223021d8c03e28d7b30`). Owner clarifications in the 2026-10-06 written-spec approval are binding.

**Authority and wire contract:** After locked DB acquire commits, Monitor obtains the Engine's current random boot nonce from an Engine-key-authenticated server-only endpoint, then creates one signed, domain-separated HMAC-SHA256 grant from its server-held Engine API key with version, unique one-use ID, opaque demand owner, exact decimal generation, authorized alias, Node, registered physical ID, boot nonce, and `expiresAtMs` not later than the returned DB demand lease expiry. Never include raw session binding. Strict Engine route requires its existing Engine key **and** exactly one valid current-boot grant; existing generation and alias headers must match grant claims byte-for-byte. Reject duplicate/ambiguous fields, malformed/canonicalization failures, expired token, bad MAC, token replay, wrong configured Node, stale boot nonce, higher-generation tombstone and a retired generation before side effects. Engine has no independent trusted physical-camera ID today: Monitor's locked DB registration/route-target check is the physical binding, and Engine only verifies that the signed physical ID is canonical and unchanged; do not claim Engine independently proves physical-world identity. Browser/query/body/heartbeat cannot supply or renew this authority. No device/source selection uses grant fields. On Engine restart Monitor may mint a new-boot grant only after fresh DB authority recheck; old-boot grants cannot replay.

**Required DB output change:** `acquire`/`renew` must use SQL `RETURNING lease_expires_at` (the exact DB-computed value, not a locally inferred `now+30s`) and `release` must return the explicit epoch-retirement outcome, using PostgreSQL `clock_timestamp()` under existing authority locks. Monitor must never mint or refresh a grant before the corresponding transaction commits. Grant expiry must be no later than the committed lease expiry, and the Engine clock/skew precondition must be proven before any production use.

**Handoff and lifetime:** Engine preflight validates and atomically reserves the one-use grant under the StreamHub condition; deferred streaming-body `add_viewer` consumes that same reservation. Reservation and attached viewer authority expire at or before the signed demand expiry. The existing 10-second serialized Monitor revalidation performs DB renewal first, then authenticated Engine lease refresh. Any failure closes/revokes that stream and releases Monitor demand exactly once. Release commits in DB before an authenticated per-demand revoke signal. Under the same StreamHub lock, an acknowledged revoke tombstones `(generation,demandOwnerId)` until all previously minted grants/refreshes expire (at most the 30-second demand lease plus 1-second sweep), and cancels unused reservations, attached viewers and in-flight refresh for that demand. A's revoke must not affect B; B's revoke between preflight and deferred attachment must block B, and a delayed signed refresh must never revive B. The release transaction must return an explicit final-epoch-retired result; only that result permits an authenticated generation-retire signal. If signalling fails, an issued grant may still start or continue capture until its signed expiry: this is a bounded post-release residual window, **not** immediate fail-closed revocation. An autonomous Engine sweeper must clear expired viewers/capture within the 30-second demand lease plus at most 1 second, even if frame iteration stalls. Reserve/replay/revoke state is bounded by a 4096-entry fail-closed cap; higher-generation monotonicity requires only the highest generation plus a retired flag. No reentry with a bare equal generation, used grant, old-boot grant, or expired lease. Require verified clock synchronization with no grace that extends DB authority, otherwise fail closed.

**Physical/alias state:** A's Engine viewer count reaching zero clears demand event/JPEG/frame queue and finalizes A's alias partial, but does not tombstone the generation while a valid B grant/reservation/lease can exist. A successful B attachment reopens capture only under its fresh grant and starts a new alias recording context. A higher observed generation permanently supersedes all lower generations; delayed retirement of lower G cannot affect G+1. No pending reservation keeps physical capture on by itself. Expired reservations and revoked viewers are cleaned without stranding capture or Monitor demands. The same mechanism applies to CAM-01 and CAM-02 on one physical generation.
